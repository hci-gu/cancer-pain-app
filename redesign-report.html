Summary

The redesign is not a surface-level color refresh. It changes the app from a generic shadcn/Tailwind interface into a bespoke, illustrated study companion with a persistent Pre-RT identity, pink page chrome, teal controls, dashboard task tiles, guided questionnaire intros, question navigation drawers, and categorized resource pages.

Primary implementation target

Replace the current global header/footer and generic cards with a redesign shell used by authenticated pages and a specialized full-screen shell for questionnaires.

Biggest product change

The home and form list become visual workflow dashboards. The daily form, initial questionnaire, study info, and Q&A are presented as clear task tiles with completion states.

Biggest engineering risk

Current questionnaire rendering is full-screen and generic. The redesign requires questionnaire-specific intro screens, progress chrome, modal resources, follow-up grouping, and adaptive text sizing.

Do not implement the browser chrome

Several mobile screenshots include Android browser controls at the very top and bottom. Treat those as viewport context only. The app should implement the pink app header, content, floating form controls, and footer, but not the OS/browser bars.

Layout rhythm

  • Authenticated pages use a full-width pink top bar.
  • Desktop content is centered, usually 640-760px wide inside a 912px artboard.
  • Mobile content is tight but still card-based, matching the 409px wide exports.
  • Footer is a full-width pink strip with GU seal and contact copy.

Typography

  • Use dark teal, heavy headings, and compact body copy.
  • Reserve large display type for page titles only.
  • Question cards use centered text and a horizontal divider under the question title.
  • Keep Swedish product text from the source data where possible.

Controls

  • Primary buttons are soft teal rounded pills.
  • Choice answers are chip buttons with stable widths and generous spacing.
  • Danger/abort action uses a saturated pink-red button.
  • Floating form nav buttons are square, pink, and bottom-right aligned.

Cards and illustrations

  • Task tiles use saturated pastel backgrounds with illustrations.
  • Cards have modest radii and minimal shadows.
  • Illustrations are meaningful content cues, not decoration.
  • Completion checkmarks sit in the top-right of task tiles.

Component Plan

The easiest path is to preserve the current data-fetching and routing, then replace the page shells and components in layers. Suggested new component boundaries:

StudyAppShell

Replaces the current authenticated part of RootPage. Owns the top bar, logo, breadcrumb trail, constrained page width, footer, and responsive spacing. It should accept optional breadcrumb items and a variant for ordinary pages versus form pages.

StudyFooter

Shared footer used on home, check-in, about, and resource pages. Match the GU seal/contact strip in the screenshots. Avoid fixed positioning on long content pages unless the content area accounts for it.

StudyTaskCard

Replacement for HomeTodoItem. Supports title, illustration, background color, completion state, disabled state, short status text, and link/button action. Use it for home and daily check-in dashboards.

QuestionnaireShell

Wraps FormPage. Owns the pink form header, progress count, progress bar, "Se alla fragor" trigger, floating previous/next/jump controls, and full-screen page scroller. This should replace ad hoc fixed elements in ProgressBar, NavigationButtons, and QuestionNavigationList.

QuestionCard

Replacement for the layout inside QuestionSelector. Handles section intro screens, normal question screens, long instruction text, info icons, question numbers, required markers, and answer controls.

AnswerChipGroup

Shared answer rendering for single-choice and multiple-choice questions. Current behavior lives in pages/form/components/Select.tsx. The redesign wants chip buttons, not generic radio rows.

QuestionListDialog

Evolves QuestionNavigationList. Must group follow-up questions under headings, highlight the active question, disable future inaccessible questions, and use a centered dialog on desktop plus a near-full-height sheet on mobile.

ResourceCategoryGrid and ResourcePage

Adds the Q&A category landing screen shown in the redesign before the existing accordions. Detail pages should reuse PocketBase resource collections but adopt the new card, accordion, image/video, and breadcrumb layout.

Flow Behavior

Home study overview
  • Route: /.
  • Show "Valkommen till studien!" and a short thank-you/introduction.
  • Cards: registration date, initial questionnaire, read study info, Q&A, daily form, after radiation treatment.
  • Completed cards show a circular checkmark in the top-right.
  • Use userDataAtom, readAboutPageAtom, and useAnswers to drive states.
Daily check-in dashboard
  • Likely route: /forms or a dedicated daily route if the product owner wants to keep all questionnaires visible elsewhere.
  • Cards include "Fyll i formular - idag", "Fyll i formular - annan dag", treatment start date, and treatment start answer/status.
  • The current FormsPage introduction copy already roughly matches this flow; preserve intent but replace the generic questionnaire cards.
Questionnaire intro pages
  • Initial questionnaire intro states: 37 questions, about 20 minutes.
  • Daily vaginal dilator intro states: 6-8 questions, about 1-2 minutes, depending on follow-ups.
  • Current section questions can render these intro screens, but they need new copy/layout handling and clear CTA buttons.
Questionnaire questions
  • Header shows "Se alla fragor", progress bar, and count such as 1/2, 3/8, or 32/37.
  • Question body is centered in a white panel on desktop, and nearly full-width on mobile.
  • Option chips auto-advance after selection, matching current onAnswer behavior.
  • Info buttons open resource/help dialogs for questions with resource metadata.
  • Long safety/violence questions need compact text and an always-visible "Lamna genast" escape action.
Submitted state
  • Display a dedicated success panel after submission instead of immediately navigating away.
  • Show a large green checkmark and a button to close the form.
  • After closing, navigate to the daily history/dashboard or questionnaire list as appropriate.
Q&A and study information
  • Category overview has six colored illustrated tiles.
  • Detail pages use breadcrumb path Start > Fragor och svar > Category.
  • Accordions are teal bars with chevrons. Expanded content lives in a white content card.
  • Media examples include diagrams, a video placeholder/player, and step-by-step illustrated instructions.

Implementation Plan

  1. Create design tokens. Update web/src/index.css theme variables for background, foreground, primary, card, destructive, border, and radius. Add named semantic utility classes only if Tailwind tokens are not enough.
  2. Build the app shell. Refactor RootPage into reusable shell components. Keep auth-gating in main.tsx unchanged initially.
  3. Replace dashboard cards. Implement StudyTaskCard and update home plus daily check-in screens. Drive card completion from existing atoms/hooks.
  4. Refactor questionnaire chrome. Move progress, list dialog, floating navigation, and section intro rendering into a coherent QuestionnaireShell.
  5. Update question controls. Rework Select.tsx and QuestionSelector.tsx to render answer chips and question cards while preserving form state, validation, dependencies, and auto-scroll behavior.
  6. Add resource category pages. Keep PocketBase resource data, but add a category overview and redesign ResourceAccordion to match the screen references.
  7. Integrate visual assets. Extract or recreate only missing assets. The current handoff already includes extracted SVG/PNG pairs under redesign/assets/ for logos, card illustrations, medical diagrams, success states, and resource artwork. Do not crop production UI from redesign/screens/.
  8. QA against references. Use Playwright or manual browser screenshots at mobile and desktop widths. Compare page layout, spacing, overflow, form progression, and route navigation.

QA Checklist

Responsive checks

  • Mobile width around 409px matches screenshot proportions.
  • Desktop width around 912-927px matches screenshot proportions.
  • No text overlaps card art, footer, form controls, or browser viewport edges.
  • Long FAQ pages scroll cleanly and keep footer placement sane.

Form checks

  • Answer chips update react-hook-form values correctly.
  • Follow-up questions appear only when dependency values match.
  • Question drawer jumps to the selected accessible question.
  • Cached form state still restores after reload.

Data checks

  • Existing questionnaire IDs continue to work, including daily form sdzkpd49ndccf5b.
  • Baseline form u6917wm639q1d01 completion state remains correct.
  • Resources still render sanitized/expected HTML from PocketBase.
  • <pre> and <post> resource filtering still works by user type.

Accessibility checks

  • All cards used as links/buttons have keyboard focus states.
  • Question chips expose selected state to screen readers.
  • Dialogs trap focus and close with Escape.
  • Color is not the only signal for completion, danger, or disabled states.

Placement workflow

  1. Start from the relevant screen in redesign/screens/ to understand layout and state.
  2. Open redesign/assets/source-previews/extracted-assets-contact-sheet.png if you need a visual scan of available assets.
  3. Pick the semantic folder, not the closest-looking screenshot: task art from dashboard-cards/, resource art from faq-categories/, medical diagrams from medical/, shell identity from logos/.
  4. Import the SVG version into React when possible. Use the PNG version only as a fallback or when the source is intentionally raster-like.
  5. Copy the selected production assets into the frontend, ideally preserving the same subfolders under web/src/assets/redesign/. This keeps implementation imports stable and prevents the design handoff folder from becoming runtime application state.

Responsive asset choice

Asset suffix Best use Notes
*-square--pNN Compact mobile cards, equal tile grids, icon-like category tiles. Use with stable card aspect ratios to prevent layout shift.
*-wide--pNN Desktop cards, wide dashboard tiles, article media blocks. Usually the best match for the desktop screen references.
*-compact--pNN Narrow dialogs, mobile accordion content, small explanatory cards. Common in medical diagrams and detailed article illustrations.
*-vertical--pNN Mobile-specific vertical diagram layouts. Use for therapy timing on narrow screens.

Asset handling rules

Do not crop full-screen references from redesign/screens/ into component assets. Do not import directly from redesign/assets/ in production code unless the team explicitly wants design handoff files in the runtime bundle. Keep alt text semantic: decorative task-card art can use alt="" and aria-hidden="true"; medical diagrams need useful alt text or adjacent explanatory text.
